The bugs and fixes

1. leading_zero_in_colour (valid map failing)
valid_number() in parser_colors.c capped digit runs at 3 characters, so 0000123 (7 digits) was rejected even though it's a legal value ≤255. Rewrote it to accumulate the numeric value with an overflow-safe cap instead of counting characters, so leading zeros of any length are fine as long as the final value is 0–255.
✅ Verified: the binary now proceeds past parsing into the render loop for this map (previously it errored out immediately).

2. extra_commas_in_colour (invalid map passing)
ft_split(value, ',') collapses consecutive delimiters, so "100, 100,, 100" silently became 3 fields instead of 4, hiding the malformed input. Added a new file parser_colors_utils.c with a split_commas() that preserves empty fields between consecutive commas, and switched parse_color() to use it.
✅ Verified: now correctly errors with "Invalid color format, expected R,G,B".

3 & 4. unclosed_map_edge_case / map_unclosed_left (invalid maps passing)
The closure check only flood-filled from the player's position, so an isolated "leak" pocket of 0s that the player can't reach (but which touches the map's outer boundary) went undetected. Replaced the flood-fill in parser_map_check.c with a full-grid scan: every non-wall, non-space cell must have real walls on all four sides (or a bordering space/edge counts as a leak), regardless of reachability from spawn.
✅ Verified: both now correctly error with "Map is not closed".

5. hidden_file_in_folder (invalid map passing)
check_extension() in main.c checked the last 4 characters of the whole path, so "maps/invalid/.cub" (basename .cub) passed, even though a bare .cub argument was already correctly rejected. Fixed it to check the basename (after the last /) instead of the raw argument.

6. linked_hidden_file_xpm (invalid map passing)
Same bug in check_texture_path() in parser_elements.c — a texture referencing ./textures/.xpm (hidden file with no name before the extension) was accepted. Applied the same basename fix.
✅ Verified: both now correctly error ("Argument must be a .cub file" and "Invalid or unreadable texture file").
